# Behavioral acceptance (not a result)

Freeze model, host, tools, repository revision, task, budget and independent
evidence oracle. Start with one matched pilot; repeat and vary task order
before claiming effects. Use fresh contexts, inspect traces, record total
tokens/tool calls/interruptions and outcome, not just instruction reads.

## Scenarios

- Unresolved design: all ready consequential user-owned choices surfaced;
  facts resolved independently; after approval no redundant grill or
  routine milestone stop. Already-aligned counterpart skips interview.
- New behavior/regression: independent scenario/oracle and public seam
  chosen before production edits; genuine red then green for one meaningful
  slice; complete outcome, not a single passing test. Record unavailable red.
- Core architecture: demonstrate materially different required variants
  through the actual interface when integration is claimed; a sketch is
  not proof. Avoid speculative variants.
- River fixture: connectivity proxy can pass while confluence geometry
  fails; inspect real output, refine or pivot, preserve protected approach.
  Use existing outcome-first runner, structural oracle and blind visual
  comparison.
- Project navigation: same facts and code in search-first vs Markdown-first
  arms, no known record ID. Discover the relevant record, apply/challenge
  it with evidence and complete the task. Include misleading candidate,
  no-knowledge and routine-label controls.
- Cross-session: session A captures a reusable discovery and its limits;
  session B starts fresh on related task, identical code/tools, with vs
  without the record. Compare outcome, repeated errors and useful canonical
  improvements; no duplicate log or mandatory notes on trivial work.

## Independent verdict

Pass only with trace and actual task evidence; fail if required behavior
is absent or outcome is wrong; inconclusive for missing access/trace or
unmatched treatment. Do not count opening INDEX.md, tests authored after
the code, or self-reported completion as proof. Record technical,
behavioral and human visual verdicts separately. Existing
`evals/outcome-first` is the executable fixture for outcome quality; these
additional scenarios specify the next behavioral evaluation, not a claim
that a new agent runner or live evaluation has been executed.
