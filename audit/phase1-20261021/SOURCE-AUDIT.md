## 6. Modernization lens (instruction audit)

Vendor guidance, with its limits:
- OpenAI Astra article [I]: remove forced multi-doc reading, repo-survey-before-edit,
  testing nudges, per-step "ask first", premature review stops, long or overlapping
  descriptions, step-by-step recipes, monolithic root skills. Keep contextual doc
  pointers, a minimal router root, explicit permission for safe workflows, current docs.
  Model-specific (GPT-6 Astra); the page recommends auditing instructions with the
  model itself before removing anything.
- Anthropic best-practices page [I]: concise, "assume Claude is smart"; match degrees
  of freedom to fragility; test with Haiku, Sonnet and Opus; keep references one level
  deep; keep SKILL.md under 500 lines; descriptions state what and when; **still endorses
  validation loops and checklists**. So "remove testing nudges" is host-divergent:
  do not port it into the Claude adapter without an eval.

Existing measurement [O]: `audit/context-20260914/REPORT.md` states no matched old/new
comparison, no percentage saving, and two probes (one incomplete). `audit/ab/DECISION.md`
is one model, 10 synthetic cases, tests implicit selection **under** an AGENTS.md routing
paragraph, not description-only discovery. Negative-trigger coverage is two cases
(`translation-negative`, `trivial-label`). **No existing eval can label any Combo rule
as overhead.** Every "remove" below is therefore [E].

### 6.1 `practices/context.md` (7.2 KB, read once by all 12 workflows)

| Section | Class | Reasoning |
| --- | --- | --- |
| Own the outcome | **invariant** | stopping point, no silent substitution, assent rules: the user's stated design. Keep. |
| Decision triage | conditional | already says resolve from evidence first; matches the Astra "less ask-first" direction. The "wait for answers / get selection before committing" lines are the only ask-first residue [E for GPT, fine for Claude] |

| Select evidence | native-overlap candidate | scoped search, batch lookups, bounded output largely duplicate harness behavior, but also act as a brake on over-reading. Remove only after an eval [E] |
| Retain and reuse | reference | provenance/staleness habits; conditional on long tasks |
| Output and continuation | native-overlap candidate | "lead with result, one short paragraph" overlaps the host's own output rules; handoff/resume lines are the unique part [E] |

Unconditional load: every workflow instructs "Read context once" (confirmed in deliver,
debug, review, plan, verify, investigate; the other six were not opened). That is a forced
read of ~1.8k tokens whether the task is a lesson or a bug. Not proven harmful;
candidate to make conditional or split (invariants always, evidence mechanics on
demand) [E]. Caveat from upstream Matt's `lazy-load-writing-for-agents` note: split only
what the model does not need as a yardstick before it starts judging.

`practices/outcome-evidence.md` (third level of the chain): a work-type table (3D,
UI, coding, research, writing) of evidence that can expose a mismatch, plus a
"Mechanical gates" section that explicitly rejects a global stop/retry loop. It is
conditional reference material, not a testing nudge. `deliver.md` ("cheapest relevant
check", "reuse still-valid checks instead of automatically rerunning each phase") and
`verify.md` ("a started command is not a pass") are risk-proportional and already
avoid the Astra-style overhead; the plan's suspicion of forced testing language mostly
does not apply to Combo's current text. `plan.md`, `verify.md`, `investigate.md` are
outcome/stopping-point driven and short (1.2-2 KB); no step-by-step recipe bloat found. [O]
