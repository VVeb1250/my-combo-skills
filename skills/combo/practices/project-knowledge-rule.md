## Combo project documentation

When writing or reviewing project Markdown and code comments:
- Preserve consequential rationale, constraints, and failure modes that code
  alone cannot explain. Keep local reasoning beside the code; link broader
  decisions and evidence from the existing project documentation.
- Use descriptive headings and coherent sections; distinguish current state,
  proposals, and historical evidence. Use lists or tables when they aid reading.
- Update affected explanations when behavior or decisions change. Maintain one
  editable source per fact and link to it instead of maintaining duplicate copies.
- Keep documentation proportional to the task: no per-task file or session diary
  by default, unrelated cleanup, or line limits that erase necessary reasoning.

For placement, supersession, or readability decisions while writing or reviewing,
read `practices/project-knowledge.md` under the installed `combo` skill once.
This practice does not create a memory store or authorize capture, recall, or export.
