# Global Technique Catalog (Phase C)

This directory is an opt-in canonical recipe shelf. Place curated, evidence-scoped Markdown in `recipes/`. A recipe is not automatically cross-project-tested. Do not copy each project's entire evidence log here; keep provenance and links to original artifacts.

The index (`index.json`) is generated by `project_kb.py` using the same schema as project-local `.combo/index.json`. It is not edited by hand. No repository-wide hook, daemon, vector DB or automatic capture is installed. Global recipes must use the same technique frontmatter/sections as local techniques.

## Usage

```bash
python /path/to/combo/tools/project_kb.py --global-catalog /path/to/this/directory global-index
python /path/to/combo/tools/project_kb.py --global-catalog /path/to/this/directory global-check
cd /path/to/project
python /path/to/combo/tools/project_kb.py --global-catalog /path/to/this/directory route --query 'thin silhouette' --engine blender --renderer eevee
python /path/to/combo/tools/project_kb.py --global-catalog /path/to/this/directory hop --from project:tech.local
```

An explicit global catalog enables project-first fallback only when no relevant local technique is selected. Project specs remain in `required` and never lose authority. `hop` follows only one edge per call; the agent chooses when to call again. Cross-scope links use an explicit `global:technique.id` target and are validated against the catalog when supplied. No global-to-project source pointers are supported by the global index as authoritative links.

Limitations: matching remains lexical; `metadata-match` is not real-world proof; the catalog must be accessible in the agent's environment and indexed after edits. Evidence links do not establish licensing or cross-project success.
