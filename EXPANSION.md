# Full source capability scope

The owner confirmed that Combo must include the noncoding capabilities of all
four packs, as well as engineering. The earlier coding-only selection is now
archived as the baseline. The expanded modular pack is installed and verified;
see [the decision and evidence](audit/ab/DECISION.md).

## Preserve capability, separate discovery

Keep curated engineering workflows and technical notes already reviewed. Add an
indexed, pinned reference library for the remaining source capabilities, with
source-specific support material where needed. A source document being retained
does not require advertising it as another global skill or loading it every turn.

The library needs a small master index, bounded domain indexes, accurate source
paths/commits, and explicit maturity/host-dependency labels. Preserve useful
procedures, examples, and templates. Do not replace hundreds of distinct source
capabilities with a few vague summary paragraphs. Do not count translations,
deprecated aliases, alternate personas, or installer copies as independent wins.

Implemented task groups, mapped in the source audit:

- Engineering: existing six paths, technical specialists, ML/data, infrastructure,
  networking, agent construction/evaluation, and relevant specialist domains.
- Research: evidence gathering, source evaluation, market/competitive analysis,
  scientific literature and database work.
- Content: voice, articles, platform-specific content, campaigns, SEO, and
  repurposing. Drafting must retain source facts and author intent.
- Learning: explanation, teaching, exercises, learner-directed practice, and
  requested course material. Scale artifacts to the actual learning request.
- Business: strategy, investor material, operational analysis, finance/billing,
  logistics, manufacturing, procurement, and planning.
- Media/design: visual direction, accessibility, presentations, motion/video,
  and native artifact production through the installed host tools.
- Productivity: elicitation, questionnaires, handoffs, agent-facing writing,
  knowledge/workspace organization, and task process improvements.

These groups guide navigation; they are not an instruction to run every group.
The A/B comparison selected direct workflow entries sharing one reference
library, with a fallback router for uncertain requests.

## Adapt host assumptions explicitly

Use the host's native browser, documents, images, spreadsheets, presentations,
connectors, and other concrete tools for their supported operations. Preserve
the source's domain knowledge without installing a second incompatible control
surface. A requested action still needs the relevant current tool/account access.

M2D remains the personal-memory authority. Source documents about alternate
memory, hooks, orchestration, notifications, or installers may support an
explicit design/integration task; they do not authorize changing the active host,
writing duplicate personal memory, spawning agents, or starting external work.
Record those host-bound capabilities as reference material with the specific
dependency or conflict, rather than silently omitting them or claiming them live.

Do not import source-wide persona, mandatory approval, automatic publishing,
autonomous delegation, logging-everything, or competing global workflow policies
as governing instructions. Concrete source procedures are interpreted within
the user's actual task, current authorization, and host instructions.

## Build and acceptance

Stage the common expanded content outside the active installed source package
until the experiment is ready. Both arms must use identical domain workflows,
references, and source revisions. Keep source provenance and the adaptation map
inspectable. Runtime references must not depend on the development checkout.

The coverage report distinguishes retained original reference material, adapted
working guidance, native-tool routing, host-bound material, and deprecated
duplicates. State which documents were body-reviewed versus metadata-classified.
Retaining a document is not proof that its full procedure has been executed.

After root reviews the matched A/B outcomes and selects a structure, update the
actual installation, relevant visibility/policy, README, installation checks,
and drift-aware rollback receipts. Preserve unrelated user configuration and the
previous installed state for rollback.
