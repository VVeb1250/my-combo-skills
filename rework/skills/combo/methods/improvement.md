# Retro and skill authoring

Start from an actual poor outcome, unexpected trace or concrete unmet capability, not a desire for more instructions. Read only selected authorized session evidence, artifacts and environment. Distinguish missing capability, discovery/activation, unclear intent, reasoning, implementation, tool/environment, interruption and weak acceptance. Identify the causal seam; if the agent never saw a relevant instruction, fix the pointer before duplicating the body. If behavior was already correct, do not add a rule.

Prefer existing native capability or deterministic structural checks for mechanical violations; replay the failure to show the check catches it. For judgment failures, sharpen a decision cue at the action where needed. Only add a method, native entry or host reinforcement when the smaller fix is insufficient. No auto-retro, transcript memory pipeline or compulsory review worker. Do not read unrelated sessions.

For a skill rework read original sources and current owners, extract decision mechanisms and assumptions, reconcile conflicts against accepted design. Write fresh, preserve justified useful content, source provenance and licenses. Inline only common responsibilities; use descriptive trigger-to-reference links for branch-specific depth. Minimize repeated always-visible metadata, measure total lifecycle cost and actual behavior, not just size or invocation. Test negative controls, interruptions and host discovery. Do not equate static checks with behavioral quality. Use the existing installer and migration discipline for activation.
